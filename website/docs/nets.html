File format

The .o2nn container

Everything the evaluator needs, in one versioned binary blob.

Header and versions

Files start with magic O2NN, then a version field:

  • v2 — value head only.
  • v3 — value head plus policy head.
  • v1 (256-wide) cannot load as v2 — the trainer converts it.

Layout (all little-endian)

BlockShapeDtype
feature_weightsINPUT_SIZE × 1024int16
feature_bias1024int16
l1 / l1_bias1024×16 / 16int8 / int16
l2 / l2_bias16×32 / 32int8 / int16
out / out_bias32 / 1int8 / int16
pol / pol_bias (v3)4352×32 / 4352int8 / int16

INPUT_SIZE is 81920 (HalfKP 40960 + Threat 40960). The policy maps 4096 from-to squares plus 256 promotions. Current nets are ~168 MB.

Naming: content-addressed

Official files are named nn-<sha256 first 12 hex>.o2nn (e.g. nn-ebdbc500e975.o2nn for v14). The loader, the server and the worker all verify name against content — a renamed or corrupt file is rejected everywhere, which is also how DefenceTest proves workers built the right engine.

Loading and embedding

  • File: setoption name NNUEFile value path/to/net.o2nn.
  • Baked in: make EXE=owen2 EVALFILE=net.o2nn CXX=g++ embeds the net; startup prints info string Owen 2 embedded net loaded (167939214 bytes).
  • Fallback: with no net at all, the handcrafted evaluator takes over.
Bench proves the bake. ./owen2 bench 6 must print nodes 32000 for the release net on every machine — the same number DefenceTest run signatures carry.
