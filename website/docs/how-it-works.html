Architecture

How Owen thinks

A move flows through four stages: board, moves, evaluation, search.

1. Board representation

The position is stored as bitboards — 64-bit integers with one bit per square — plus Zobrist hashes, castling rights, en-passant state and clocks. Sliding pieces use magic bitboards: precomputed attack tables indexed by masked occupancy. Make/unmake is incremental, so trying a move costs almost nothing.

2. Move generation

Pseudo-legal generation followed by legality filtering. Correctness is guarded by perft: the well-known Kiwipete position must yield exactly 97862 nodes at the reference depth. Run it yourself: ./build/owen2-perft.

3. NNUE evaluation

Leaves are scored by a neural network, not hand-tuned piece values:

  • Features: HalfKP (40960) + Threat (40960) = 81920 inputs.
  • Layers: 1024 → 16 → 32 → 1 (value), plus a 4352-output policy head.
  • Arithmetic: int8/int16 quantized; AVX2 paths where the CPU allows.
  • Shipping: versioned .o2nn files, optionally baked into the binary (see Network format).

With no network loaded the engine falls back to a small handcrafted evaluator — enough to play legal, sensible chess while you train your first net.

4. Marrow Tree Search

Instead of alpha-beta's depth-first minimax with null-move pruning and late-move reductions, Owen grows one shared tree best-first:

  • Selection: UCB1 over sorted children (Q + C·√(log N / n)); unvisited children expand eagerly.
  • Expansion: one legal move becomes one child, with priors from transposition-table moves, captures and promotions.
  • Backup: negamax value plus proof-urgency propagation (exact AND/OR proof numbers with mate-distance preference).
  • Depth by uncertainty: no null-move, no classic LMR — effort flows to the lines the tree is least sure about.
  • Threads: Lazy SMP trees share the table; per-thread sharding keeps replacement sane.
Fixed budgets, honest reporting. go depth D maps to a visit budget (depth 4 ≈ 12k visits); the reported depth is the maximum tree depth actually reached. bench is deterministic: depth 6 on the v14 net always yields 32000 nodes, bestmove e2e4.

5. Move choice and output

The most-visited root child (tie-broken by value) becomes bestmove, preceded by a standard info depth/score/nodes/nps/time/pv line — the same lines in bench output. See UCI reference for the full protocol.
