Training pipeline

Games → data → net → gate → promotion. Repeat forever.

1. Generate data

The engine plays itself and records positions with game outcomes: 

./build/owen2-sdata --games 100000 --out data/sdata.bin
  • Openings come from curated books (tools/book-200.epd) for variety.
  • The sdata v2 container (71 bytes/position) preserves castling rights and en-passant so samples are unbiased; legacy 69-byte files still read.
  • Generation is chunked and resumable (tools/selfplay_loop.py, tools/merge_chunks.py) — many machines can contribute shards.

2. Train the net

python trainer/train.py --sdata data/sdata.bin --out nets/o2-new.o2nn --device cuda
# --device cuda | mps | cpu

The PyTorch trainer (trainer/, full details in its README) fits value and policy heads with large batches across epochs. Distillation from a stronger teacher is documented separately in DISTILL.md.

3. Gate on DefenceTest

A candidate net never ships on vibes: it runs as the new side in a DefenceTest SPRT match against the current net (see Worker API reference). Green means statistically stronger — promote it to nets/active.o2nn and cut a release. Red means back to step 1 with more or better data.

Naming rule. Publish gated nets as nn-<sha256[:12]>.o2nn so every consumer can verify content by name (see Network format).
